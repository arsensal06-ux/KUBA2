# KUBA — готовый сайт для GitHub Pages

**На компьютере ничего устанавливать не нужно.** Не нужен Python, Node, Git-клиент, терминал или отдельный хостинг. Весь запуск — через сайт GitHub.

## 1. Создай репозиторий

На GitHub нажми **New repository**:
- имя: `kuba`;
- видимость: **Public**;
- включи **Add a README file**;
- нажми **Create repository**.

Это самый простой вариант запуска; в закрытом репозитории доступность Pages зависит от тарифа. Никогда не добавляй в репозиторий пароли, серверные ключи Firebase и файлы service account. Web-конфигурация Firebase в `config.js` — публичные параметры, доступ защищается правилами базы.

## 2. Включи публикацию

В репозитории открой **Settings → Pages**. В блоке **Build and deployment** выбери **Source → GitHub Actions**. Больше никакой ручной настройки сборки не нужно.

## 3. Загрузи файлы

1. Распакуй этот архив.
2. В репозитории нажми **Add file → Upload files**.
3. Перетащи **все файлы и папки из архива**, включая **`.github`**. Не загружай сам ZIP и не помещай весь сайт в дополнительную вложенную папку.
4. Нажми **Commit changes** в основной ветке `main` (или `master`).

Правильная структура репозитория:

```text
.github/workflows/deploy.yml
index.html
admin.html
setup.html
assets/
images/
README.md
firestore.rules
...
```

`index.html` должен быть сразу в корне. Если `.github` не видно в распакованном архиве, включи показ скрытых файлов: на Mac — `Cmd + Shift + .`; в Windows — «Вид → Показать → Скрытые элементы». После загрузки проверь, что `.github/workflows/deploy.yml` есть в репозитории.

## 4. Открой сайт

Во вкладке **Actions** дождись зелёной галочки у **Publish KUBA website**. Обычно это занимает несколько минут, но зависит от очереди GitHub. Ссылка появится в **Settings → Pages**, вида:

```text
https://ТВОЙ-ЛОГИН.github.io/kuba/
```

Если workflow запустился до включения Pages и завершился ошибкой, после шага 2 выбери **Actions → Publish KUBA website → Run workflow**. В настройках нового репозитория Actions должны быть разрешены; если их запретила организация, потребуется её администратор.

При каждом следующем изменении файлов в основной ветке GitHub сам проверяет файлы и публикует сайт. Команды, сборка и установка библиотек с твоей стороны не требуются. Дизайн и изображения уже включены в проект.

## Админка и обновления в реальном времени

Админка находится по адресу сайта с добавлением **`admin.html`**, например `https://ТВОЙ-ЛОГИН.github.io/kuba/admin.html`.

GitHub Pages публикует HTML/CSS/JS, но **не является базой данных**. Туры, тексты, заявки и статусы меняются у всех посетителей через Firebase, уже предусмотренный в исходном проекте. Эти изменения после успешного сохранения НЕ требуют нового commit или развёртывания GitHub.

Для настройки открой **`setup.html`** на опубликованном сайте либо ссылку **«Первый запуск и настройка»** в админке. Там есть пошаговая инструкция, проверка чтения базы и кнопка копирования домена. Всё делается через браузер:
- разрешить домен `ТВОЙ-ЛОГИН.github.io` в Firebase;
- включить Email/Password;
- применить `firestore.rules` через Firebase Console;
- войти аккаунтом владельца и подтвердить email.

В архиве нет твоего пароля, и загрузка кода на GitHub не создаёт аккаунт и Firestore автоматически. В исходном коде указан проект `kubanadventures`; настройка предполагает, что он принадлежит тебе и у тебя есть доступ к Firebase Console. Если проекта у тебя нет, нужен собственный Firebase-проект и его web-конфигурация в `assets/js/config.js`.

**До подключения Firebase витрина показывает исходные туры и картинки, но публикация через админку и отправка реальных заявок не считаются настроенными.** Мы не подменяем облачное сохранение локальным «успехом».

Если в Firebase уже есть другие приложения, перед применением наших rules сохрани текущие правила: файл запрещает доступ к другим коллекциям и требует осознанного объединения.

## Перед реальными клиентами

Проверь исходные контакты, цены, статистику и утверждения о сертификатах; добавь юридически согласованную политику обработки данных до сбора персональных данных. В пяти регионах исходного проекта не было туров — их нужно добавить, а не публиковать вымышленные цены. Обложки — AI-иллюстрации, не фотографии конкретных маршрутов. Встроенная форма отправляет заявку, не принимает оплату.

## Проверки

`TEST-REPORT.md` содержит отчёт. Папки `scripts` и `tests`, `package.json` предназначены для автоматической проверки и разработчиков; **тебе не нужно их запускать или устанавливать Node**. Workflow использует готовую среду GitHub и публикует только страницы, стили, скрипты и изображения. Python в процессе публикации не используется.

Официальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
