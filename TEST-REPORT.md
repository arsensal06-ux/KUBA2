# Отчёт о проверке

## Автоматическая проверка приложения

- **25 проверок E2E — успешно**, два изолированных browser contexts с раздельным localStorage.
- Firebase в E2E заменён тестовой моделью Auth/Firestore. Записи в реальный проект не выполнялись.
- **9 проверок localhost-демо — успешно**, реальные JS-модули проекта, внешняя HTTPS-сеть заблокирована.
- Ошибок JavaScript в сценариях не обнаружено.

Проверены:

1. Приоритет server snapshot над старым локальным кэшем.
2. Отказ входа с неверным паролем в модели Auth; production-код не использует псевдо-сессии.
3. Изменение заголовка, контактов, цены и тура без перезагрузки страницы посетителя.
4. Ошибка записи не превращается в ложное сообщение о публикации и не меняет витрину локальным черновиком.
5. Безопасная проверка URL обложки; схема javascript: отклоняется.
6. Создание и удаление туров; экранирование пользовательских текстов от HTML/XSS.
7. Сохранение активной категории при получении обновления.
8. Отправка заявки, получение администратором, изменение статуса в личном кабинете.
9. Локальная синхронизация demo через storage/BroadcastChannel, без обратного перезаписывания устаревшего кэша.
10. Полностью пустой каталог удаляет все карточки, а снятый с публикации тур больше нельзя отправить как новую заявку.
11. Валидация телефона и понятные сообщения об ошибке.
12. Отсутствие горизонтального переполнения в проверенных разделах и на экране шириной 390 px.

## Визуальная проверка

Рендеры проверены на desktop 1440 px и mobile 390 px: главный экран, семь регионов, «О нас», вход, регистрация, кабинет, детали тура, заявка и ошибка валидации, админская авторизация, заявки, каталог и редактор текстов. Проверены читаемость, обложки, отступы и отсутствие наложений; исправлены накладывавшийся индикатор соединения, поле имени без стилей, отсутствовавшая иконка редактирования и гонка переходов исходного шаблона. Низкоразрешённые промежуточные обложки заменены полноразмерными WebP.

## Что НЕ проверено

- Реальный Firebase пользователя: текущие deployed rules, существующий аккаунт, подтверждение email, Authorized domains и межустройственная синхронизация в production.
- Компиляция/развёртывание включённых Firestore rules на реальном проекте; правила необходимо согласовать с текущей базой и проверить перед публикацией.
- Оплата, платёжные провайдеры, уведомления по email/Telegram, CRM: интеграций в этой версии нет.
- Достоверность исходных цен, контактов, статистики, сертификатов, доступность маршрутов и юридическая готовность к сбору персональных данных.

**Результат проверки не означает, что сайт уже размещён в интернете.** Финальный acceptance-тест после настройки Firebase описан в README.

## Проверка версии для GitHub Pages

- В архив добавлены GitHub Actions workflow, `.nojekyll`, страница первого запуска, иконка вкладки и инструкция без локальной установки программ.
- Повторены 25 E2E и 9 demo-проверок по адресу с префиксом `/kuba/`, который соответствует структуре project site на Pages.
- Дополнительно успешно выполнены 14 smoke-проверок: корневая страница под путём репозитория, исходный каталог без облака, отсутствие ложного входа без Firebase, переходы между админкой и настройкой, относительная иконка, консольные ссылки, guard админки, мобильная ширина, отсутствие отсутствующих локальных ресурсов и ошибок JavaScript. В smoke-тесте облачный SDK подменён заглушкой; реальная база не изменялась.
- YAML workflow проверен: события push main/master и workflow_dispatch, разрешения pages/id-token, путь артефакта `_site`, последовательность официальных Pages actions.
- Скрипт `scripts/verify.cjs` успешно проверяет комплектность файлов, относительные ссылки, синтаксис модулей и наличие обложек. GitHub автоматически выполняет эту проверку перед публикацией.
- Отдельно проверено отображение главной, админского входа и нового setup на desktop и mobile.

**Настоящий запуск workflow в аккаунте GitHub ещё не выполнялся**: репозиторий не предоставлен. Для публикации владелец один раз выбирает Settings → Pages → Source → GitHub Actions, разрешает Actions, затем загружает содержимое архива в основную ветку. Настройка реального Firebase также не выполнялась и не подменена локальным успешным сохранением.
