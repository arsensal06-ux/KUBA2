Запуск без установки программ

GitHub публикует витрину. Firebase хранит изменения и заявки. Всё настраивается через браузер — Python, терминал и отдельный сервер не нужны.

Подключение к базе

Проверяем соединение…

Проверяется только чтение витрины. Права записи, почта и заявки подтверждаются отдельным тестом ниже.

01

Опубликуй сайт на GitHub

  1. Создай Public-репозиторий с именем kuba. Включи Add a README file.
  2. В репозитории открой Settings → Pages → Source → GitHub Actions.
  3. Распакуй архив и загрузи содержимое в корень репозитория: index.html должен быть сразу в корне. Обязательно загрузи папку .github.
  4. Нажми Commit changes. Открой вкладку Actions и дождись зелёной галочки у Publish KUBA website.

Ссылка появится в Settings → Pages. Следующие изменения файлов в основной ветке публикуются автоматически. Если первая попытка была до включения Pages, выбери Actions → Publish KUBA website → Run workflow.

02

Разреши домен сайта в Firebase

В исходном коде уже указан проект kubanadventures. Для работы админки нужен доступ владельца к этому проекту.

Открыть настройки Firebase Auth ↗

В Authentication → Settings → Authorized domains нажми Add domain и вставь:

Домен опубликованного сайта

Только домен, без https:// и пути репозитория. При локальном открытии файла здесь нет домена GitHub — этот шаг делается после публикации.

В Authentication → Sign-in method включи Email/Password, если он ещё выключен.

Если указанный Firebase-проект не твой или больше не существует, потребуется свой проект. Его web-конфигурация заменяется в assets/js/config.js через редактор GitHub; GitHub не создаёт облачную базу сам.

03

Примени правила доступа

Открыть Firestore ↗

Если базы нет, создай Firestore Database. Во вкладке Rules вставь готовые правила из файла firestore.rules в репозитории и нажми Publish.

Если в этом Firebase-проекте уже работают другие приложения, не заменяй их правила целиком: сначала сохрани копию и согласуй правила. Наш файл запрещает доступ к прочим коллекциям. Не включай «доступ всем на запись».

Посетители читают витрину. Менять её может только владелец с подтверждённой почтой. Заявку видит только её автор или администратор.

04

Войди и проверь изменения

Администратор в исходном проекте: . Пароль не лежит в архиве: используй пароль своего Firebase-аккаунта, не пароль GitHub или почтового ящика.

  1. Если аккаунта ещё нет, создай его через Authentication → Users → Add user. Если он уже есть — не создавай дубликат.
  2. Открой админку, введи правильный пароль. При неподтверждённой почте нажми Подтвердить email, открой письмо, перейди на главную страницу, нажми «Выйти» и войди в админку снова.
  3. Измени заголовок и нажми Сохранить и опубликовать тексты.
  4. Открой сайт в другом браузере или на телефоне. Заголовок должен обновиться без перезагрузки. Отправь тестовую заявку и проверь её статус в кабинете.

Что готово, а что требует твоих данных

Обложки, дизайн, мобильная версия, формы и синхронизация включены в архив. Сайт показывает исходный каталог даже до подключения базы, но отправка реальных заявок и публикация через админку требуют настроенного Firebase.

В пяти регионах исходного проекта не было туров. Их можно добавить в админке. Перед публичной рекламой проверь цены, контакты и заявления о сертификатах; до сбора персональных данных добавь согласованную политику обработки данных. Обложки — AI-иллюстрации, не документальные снимки маршрутов.
